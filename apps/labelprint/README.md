# 标签打印系统

用网页给 Brady BBP12 打印机打样品标签。不用装任何软件，浏览器打开网页就能用。

---

## 一、日常使用

### 1. 打开网页

- **通过实验室工作台使用**：登录工作台后打开顶部「标签打印」；工作台服务端代
  理本机标签服务，浏览器不直接访问 8080。
- **管理员本机排查**：仅在打印服务器上访问 `http://localhost:8080/`。
- 打印服务从 TASK-87 起只监听本机；普通用户不要直接打开 8080，直接访问不会绕过
  工作台的租户开关。

打开后页面顶部有一条状态条，会显示"打印机就绪"或者"打印机未就绪：具体原
因"，随时能看出打印机现在能不能用。

### 2. 打印标签（三步）

**第一步：录入样品数据**

- 顶部填一下"操作人"（会记住，下次打开自动填好）和"每个样品打印份数"。
- 把 Excel（.xls/.xlsx）或 CSV 文件拖进虚线框，或点"点击选择文件"选一个——
  表格会自动读出来填好。也可以不上传文件，直接在下面的表格里手动一行行填
  （样品名称必填，浓度、260/280、备注可以留空），点"+ 加一行"加更多行。
- 填好后点"**预览**"。

**第二步：预览并勾选要打印的标签**

- 每张标签的实际打印效果都会显示出来，图下面有一个"打印这张"的勾选框，默认
  全部勾上，不想打的取消勾选就行。
- 顶部会显示"将打印 N 张"，跟"份数"和勾选的张数联动。
- 确认没问题后点"**打印**"。
- 送出后会提示"已送出 N 张"——**这只代表数据已经交给打印机，标签有没有真的
  印出来、印得对不对，要看打印机那边实际出纸情况**，RAW 打印通道本身不会告
  诉网页"纸真的出来了"。

如果表格有问题（比如少了必须的列、内容长到贴不下），网页会用中文直接提示该
改哪里，照着改就行。

### 3. 查看历史 / 重新打印

- 网页右上角点"查看历史 / 重打"，进历史页。
- 可以按样品名称关键字搜索之前打印过的记录，看到时间、批次、份数、操作人、
  打印是否成功。
- 想重新打某一条，点它那一行的"重打"按钮，会自动跳回首页并把数据填好，重新
  预览确认后再打印。

## 二、出问题了怎么办

**先双击桌面上的"标签打印 - 自检"图标。**

桌面上找不到这个图标的话，手动找过去也行：打开"文件资源管理器"（任务栏那个
黄色文件夹图标），点最上面的地址栏，输入 `C:\lab-workspace\app\labelprint`，回车，
双击里面的 `verify.bat`。

它会自动做 5 项检查（标签渲染、打印指令生成、打印链路、打印机状态、自带测试
套件），**过程中不会打出任何实物标签**，跑完会打印一份中文报告，例如：

```
[1/5] 标签渲染 .................. 通过
[2/5] TSPL 指令生成 ........ 通过
[3/5] 打印链路（不出纸） ........ 通过
[4/5] 打印机状态 ................ 通过
[5/5] 自动化测试套件 ............ 通过
```

如果哪一项没通过，**把这份报告整段复制或截图**，发给负责维护的人就行，不用
自己排查。常见情况：

- **状态条提示"打印机未就绪"**：多半是打印机没开机、USB 线松了、卡纸或标签
  纸用完了，状态条会给出具体原因，照着处理，处理完刷新网页即可。
- **网页打不开**：确认这台电脑是否开机、你的设备是否连了实验室内网。
- **打出来的标签黑白颠倒、内容跑偏或被裁掉**：先别继续批量打，把这张标签和
  报告一起反馈给维护的人，可能需要调整一个打印参数（不是你这边能改的设置）。

## 三、给管理员：安装、重装与卸载

以下操作需要在这台电脑上用管理员权限打开 PowerShell 执行，日常打印标签的人
不需要看这一节。

> 2026-10-23（TASK-94）起，标签打印服务并入 lab-workspace 仓库（`apps/labelprint/`），
> 与工作台同一个安装包、同一次安装、同一个版本号。部署、升级与回滚见仓库
> `docs/label-print.md` 第 6 节与 `docs/deployment.md`；下面只列与本服务相关的要点。

### 服务是怎么跑起来的

- 开机自动启动，不需要任何人登录 Windows。
- 通过 Windows"计划任务"里的 `LabWorkspace-LabelPrint` 实现：开机触发
  `C:\lab-workspace\deploy\run-labelprint.ps1`，它会循环拉起
  `python -m labelprint.app`，服务进程一旦意外退出，5 秒后自动重新拉起。
  Python 用安装包自带的嵌入版 `C:\lab-workspace\python`（3.13.15，依赖版本锁定在
  `requirements-win.txt`），不依赖机器上另装的系统 Python。
- 代码在 `C:\lab-workspace\app\labelprint`，每次安装整体替换；打印历史库仍在
  `C:\labelprint\data\labelprint.db`，安装不会动它，并在每次安装前自动备份到
  `E:\lab-workspace\backups\labelprint_<时间>.db`。
- 只监听本机 `127.0.0.1:8080`，远程用户必须经过 lab-workspace 服务端代理。

### 安全边界：这个服务没有登录密码，请知悉

这个服务**没有设登录或密码**。它默认只监听 `127.0.0.1:8080`，远程用户必须
通过 lab-workspace 的服务端代理，由工作台校验登录身份、账号开关和启用设备。
不要把 `LABELPRINT_HOST` 改成 `0.0.0.0`，否则会绕过工作台权限。

### 安装、升级、卸载

都跟随工作台一起做：开发机 `bash infra/windows/build-bundle.sh` 生成安装包，
目标机执行 `C:\lab-workspace\incoming\deploy\install.ps1`。安装日志最后会依次出现
「网页服务已启动」「标签打印服务已启动（版本 xxx）」。卸载用
`C:\lab-workspace\deploy\uninstall.ps1`，不会删打印历史库，也不会碰 BarTender、
Brady 驱动或实验室现有的打印模板。

### 技术细节（进阶，一般用不到）

- 服务日志：`E:\lab-workspace\logs\labelprint.log`
- 版本：`http://127.0.0.1:8080/api/status` 返回的 `version` 与 `C:\lab-workspace\app\VERSION` 相同
- 打印机名默认 `Brady BBP12`；多台设备在 `C:\lab-workspace\config\lab.env` 里配
  `LABELPRINT_PRINTERS_JSON`（每项包含 `id`、显示名和 Windows 打印队列名），守护脚本只把
  `LABELPRINT_` 开头的配置传给本服务
- 如果实物验证发现标签黑白颠倒，改 `labelprint\config.py` 里的
  `INVERT = False` 为 `True`，不需要改其它代码
- 计划任务以 `SYSTEM` 身份运行（已实测确认 SYSTEM 能正常访问 Brady BBP12 打印队列）
- `docs/progress.md` 是并入前独立仓库的进度记录，仅作历史参考

### 给以后改 `labelprint\render.py` 的人

开发机（Mac）和目标机用的中文字体不是同一款：目标机是 Windows 自带的微软
雅黑，开发机优先用 Office（Word/Excel/PowerPoint 任一个装了都行）自带的
微软雅黑，找不到才退回华文黑体兜底（详见 `labelprint\fonts.py`）。但两台
机器终究是不同的字体渲染引擎，同一段文字量出来的实际字形大小可能有细微
差异——标签排版的边界判断（下划线会不会跟第二行糊在一起、内容会不会被
挤出画布）都是按"实际字形"现算的，不是按标称字号估算，理论上两台机器
应该结论一致，但**没有在目标机上实测过的改动不能当作已验证**。改完
`render.py` 之后，合并前必须在目标机上跑一次 `verify.bat`（第 1 项"标签
渲染"和自带测试套件都会覆盖到），本机 `pytest` 全绿不构成放行依据。
