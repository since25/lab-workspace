# 常用耗材库存（固定规格槽位）

## 范围

「部门物料」继续用于查询 OA 采购记录；「常用耗材」管理细胞房高频耗材的**实物库存**。2026-10-21 起改为**固定规格槽位**：每行是实验室固有的一个规格（如「200µL 滤芯吸头」「24孔板 TC」），品牌货号挂在槽位下，只用来识别采购入库。库存数记在槽位上，不按品牌分开数。

| 表 | 含义 |
|---|---|
| `material_items` | 采购记录（OA 每周增量同步），代表「买过什么」，本模块不修改 |
| `consumable_stock` | 一行 = 一个槽位，代表「现在还有多少」；`slot_key` 为内置模板标识，`baseline_at` 为基线时间 |
| `consumable_stock_checks` | 盘点（`kind=check`）和入库（`kind=inbound`）历史，改前/改后/操作人/时间/备注 |
| `consumable_stock_skus` | 货号记忆：归一键（名称\|品牌\|规格）→ 槽位；`stock_id` 为空表示该货号已排除 |
| `consumable_stock_links` | 每条采购记录与槽位的对应和处理状态 |

## 工作流程

```
① 建立槽位模板 → ② 匹配采购记录 → ③ 人工核对（确认归属 + 第一次盘点 = 基线）→ ④ 定期：新采购确认入库 + 定期盘点
```

1. **建立槽位模板**（管理员，常用耗材页按钮）：按内置模板补齐缺失的槽位，数量 0、待核对；已存在的槽位（包括改过名称/单位的）不动。
2. **匹配采购记录**（管理员）：扫描展示部门中尚未归入的启用采购记录：
   - 货号以前确认过 → 直接归到原槽位（排除过的直接排除），不再问人；
   - 否则按规则给出「建议槽位 + 把握（高/中/低）」，进入核对工作台「待确认归属」；
   - 规则没命中的（试剂盒、抗体、细胞、动物耗材等长尾）不建记录，继续在部门物料里查；以后新增槽位或规则时，再点匹配还能归入。
3. **核对工作台 · 待确认归属**：逐条「确认」（可在下拉里改归到别的槽位）或「排除」。确认/排除会记住该货号，同货号的其他待确认记录一并处理。「按建议确认全部『高』把握」只处理高把握且未改动建议的行。
4. **第一次核对 = 基线**：在常用耗材页对槽位点「核对」填现有数量。基线日当天及以前的采购视为已数在内，只作参考，不加数。
5. **核对工作台 · 待入库**：槽位有基线后，基线日以后（有收货日期用收货日期）归入的采购会出现在这里。点「入库」按采购数量加数（可改数字），写一条入库历史；已在盘点里数过的点「不加数」。采购单位与槽位单位不同时提示「≠ 槽位单位」，按槽位单位填写。
6. **定期盘点**：每月对槽位点「核对」，覆盖为实际数量。超过 30 天未盘点显示「需复核」。

## 计数口径

- **按采购单位整箱/整包计，不拆**。塑料耗材一般整箱出库，数到 0 即需要采购，不管外面有没有已开封的；所以状态里 0 显示「需采购」。
- 槽位的「单位」默认取模板（塑料/细胞耗材多为箱，培养基为瓶），管理员可在编辑里改。

## 状态

| 状态 | 接口值 | 条件 |
|---|---|---|
| 需采购 | `out` | 已核对且 `quantity <= 0` |
| 需复核 | `stale` | 从未核对（数量未知，不当作 0），或距最近核对超过 30 天（`STOCK_STALE_DAYS`） |
| 正常 | `ok` | 其余 |

入库加数不更新「最近核对」，不会让需复核变正常；只有盘点会。

## 列

类别（大类/子类）｜槽位（单品槽位下方显示品牌/规格）｜已挂货号（点开看品牌+货号）｜单位｜当前库存｜状态（有待入库时显示「待入库 N」）｜最近核对（含基线日）｜消耗/月｜最近采购｜操作。

- **消耗/月**：基线后盘点满 28 天时按**盘点差**计算 = 基线后每次盘点的减少量之和 ÷ 基线到最近盘点的月数（入库加数不算消耗）；不满时按已归入的同单位采购估算 = 采购量合计 ÷ 首末采购跨越的月数（至少 2 笔），数字后带「*」。
- **最近采购**：已归入该槽位的最近一笔采购（日期 + 数量 + 单位）。

## 槽位模板（`apps/web/src/lib/consumable-slots.ts`）

按 2026-10 生产采购台账反推、经用户确认：非 TC 板、U 底板、150mm 皿、多层瓶不算常用；培养添加物并入培养基；长尾试剂只为常用单品建槽位。

| 大类 | 子类与槽位 |
|---|---|
| 细胞耗材 | 细胞培养板：6/12/24/48/96 孔 TC；培养皿：60mm、100mm；培养瓶：T25、T75；细胞筛：40µm、70µm；冻存管：2mL |
| 塑料耗材 | 吸头：10/200/1000(1250)µL × 普通/滤芯；离心管：1.5/2.0/15/50mL；血清移液管：5/10/25/50mL；PCR 耗材：8连管、8连管管盖、96孔 PCR 板、封板膜/封口膜 |
| 通用耗材 | 实验耗材：60mm 细菌培养皿、巴氏吸管、10/50mL 加样槽；手套：S/M/L；日用防护：垃圾袋、口罩、擦手纸、液氮标签、鞋套 |
| 培养基 | 基础培养基：DMEM 高糖、DMEM/F-12、RPMI 1640、IMDM、Opti-MEM；添加物：FBS、双抗、胰酶、PBS、生理盐水、细胞冻存液 |
| 常用试剂 | 单品：QuickExtract DNA 提取液、Lipofectamine MessengerMAX、jetOPTIMUS、DH5α 感受态、2× Phanta Max Master Mix |
| 其他 | 无模板，管理员手工新增 |

模板只放通用规格名和公开产品名。增删槽位：页面上直接「新增槽位」/「删除」即可（手工槽位没有自动匹配规则，靠核对工作台改归挂货号）；要让新规格也能自动匹配，在 `consumable-slots.ts` 加模板和规则并补 `consumable-slots.test.ts`。

### 匹配规则与把握

- 名称 + 品牌 + 规格合并后 NFKC、转小写、去空格，按规则顺序第一条命中为准（PCR 耗材、冻存管、细菌培养皿排在通用规则前，避免「96孔板封膜」落到培养板）。
- 吸头按容量（10/200/1000-1250）和是否「滤芯」；培养板按孔数，`未TC/non-TC/U底` 不归位，包被板为「中」；培养瓶台账里都是未 TC，归位但为「中」；150mm 皿、多层瓶不归位。
- 名称像试剂盒/抗体（试剂盒、kit、ELISA、assay、抗体、mAb）且槽位不是常用试剂 → 「低」；OA 小类与槽位大类不符（耗材槽位但小类是试剂，或试剂槽位但小类是耗材）→ 「中」。
- Polyplus 其他产品、Phanta Ultra/Uc 会以「低」建议到 jetOPTIMUS / Phanta Max 槽位，由管理员排除或手工建槽位。
- 2026-10-20 生产导出离线试跑：58 个槽位，886 条启用采购中 196 条给出建议（高 183、中 9、低 4），690 条长尾不归位；只有 48孔板 TC 无采购记录。

货号归一键沿用 `stock-normalize.ts`（品牌别名、品目同义词、「货号:xx 名称:xx」、200T 规格统一）。

## 类别配置

默认类别 = 模板中出现的类别 + 「其他」。可通过 `MATERIAL_STOCK_CATEGORIES_JSON` 覆盖（只写名称数组即可，`keywords` 字段仍兼容但不再使用）；配置里没有的类别，其模板槽位不会建立。配置损坏时接口返回 503。生产 `lab.env` 目前未设置该项，使用默认值。

## 权限

| 操作 | 普通成员 | 管理员 |
|---|---|---|
| 查看槽位、已挂货号、核对历史 | 可以 | 可以 |
| 新增/编辑/删除槽位、核对数量、建立模板、匹配采购 | 不可以 | 可以 |
| 核对工作台（确认归属、排除、入库、不加数） | 不可以 | 可以 |
| 提交库存校对请求 | 可以，待管理员批准 | 可以，待批准 |

成员或 agent 仍通过「库存校对请求」建议数量，见 [`agent-mcp.md`](agent-mcp.md)。

## 核对与并发

- 核对提交 `{ quantity, note, expected_revision }`；`revision` 不一致返回 409。第一次核对同时写 `baseline_at`。
- 入库在事务里锁槽位行后加数并 `revision + 1`，写 `kind=inbound` 历史；不检查 `expected_revision`（加法不会覆盖别人的数）。
- 已入库的采购记录不能再改归属；同一条记录只能入库一次。
- 删除槽位会级联删除核对历史和已挂货号，对应采购记录的归属置空；有待审批的库存校对请求时拒绝删除。

## API

```bash
# 列表（category 可为大类或「大类/子类」；status: out|stale|ok）；返回 items[].skus/baseline_at/usage_basis/pending_inbound 与 review{pending,inbound}
curl -b cookie.txt 'http://127.0.0.1:3000/api/v1/materials/stock?category=塑料耗材'
# 建立槽位模板（管理员）→ {templates, created, skipped}
curl -b cookie.txt -X POST http://127.0.0.1:3000/api/v1/materials/stock/templates
# 匹配采购记录（管理员）→ {scanned, suggested, known, excluded, unmatched}
curl -b cookie.txt -X POST http://127.0.0.1:3000/api/v1/materials/stock/sync
# 核对工作台列表（管理员）：view=pending|inbound|done
curl -b cookie.txt 'http://127.0.0.1:3000/api/v1/materials/stock/links?view=pending'
# 处理一条采购记录（管理员）：action=confirm(stock_id?)|exclude|stock(quantity?)|skip
curl -b cookie.txt -H 'Content-Type: application/json' -X POST -d '{"action":"confirm","stock_id":3}' \
  http://127.0.0.1:3000/api/v1/materials/stock/links/1234
# 盘点（管理员）
curl -b cookie.txt -H 'Content-Type: application/json' -X POST \
  -d '{"quantity":6,"note":"月度盘点","expected_revision":2}' http://127.0.0.1:3000/api/v1/materials/stock/1/check
```

完整定义见 `api-contract.md`。

## 迁移与部署

- `db/migrations/013_consumable_slots.sql`：`consumable_stock` 加 `slot_key`、`baseline_at`（已核对的旧条目回填为最早核对时间）；`consumable_stock_checks` 加 `kind`；新建 `consumable_stock_skus`、`consumable_stock_links`。不修改 `material_items`，不删除旧条目。
- 升级后旧的「按货号」条目仍在（`slot_key` 为空）。2026-10-21 用户同意清掉线上由旧「生成候选」建的条目；清理在部署时单独执行，见当轮进度日志，执行前先备份。
- 上线后操作顺序：建立槽位模板 → 匹配采购记录 → 核对工作台确认归属 → 逐槽位第一次核对（基线）。
- 回滚：恢复部署前备份；仅回滚代码时新表和新列不影响旧版本运行（旧版本不读这些列）。

## 明确不做

- 不拆箱计数，不做箱→盒换算；不设安全库存线（0 即需采购）。
- 不自动加数：入库必须管理员在工作台逐条确认；不自动扣减。
- 不做库位、批次、效期、序列号；不自动生成 OA 请购单。
- 不向普通成员开放直接改库存；成员/agent 只能提交待批准的库存校对请求。
- 不在页面或日志中展示真实部门、账号、采购明细。
