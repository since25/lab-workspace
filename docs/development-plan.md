# 开发计划

> 状态（2026-10-12）：Phase 0–3 已完成并在开发机通过测试；Phase 4 的部署脚本已就绪，待 windows-wg 恢复在线后安装验收。

## Phase 0：准备

- 固化需求边界、权限规则和数据生命周期
- 确认 windows-wg 上 Node.js、PostgreSQL 16、R 的原生安装方式与开机自启方案
- 设计导入模板和校验错误格式
- 从 EditR_wang 标记可迁移的 Sanger/Nanopore 算法函数

## Phase 1：平台底座

- 登录、会话、管理员创建账号
- PostgreSQL migration、健康检查、审计日志
- 临时任务目录、TTL 清理器、统一错误处理
- windows-wg 原生部署说明（服务自启、端口、备份）

验收：管理员能创建/停用用户；普通用户不能访问管理接口；过期任务文件自动消失。

## Phase 2：Guide 与资源库

- 用户独立 Guide CRUD、序列校验和 CSV 导出
- 细胞库 xlsx/csv 导入（多工作表按架号读取、层号向下填充、待核对标记）、预览、错误行下载、查询、单条录入、修改管数与修改历史
- 部门物料：管理员导入采购系统导出并增量更新，按指定部门查询与状态筛选；普通成员二次确认申请已用完，管理员批量批准、驳回和恢复（已部署，OA 每周六 03:00 自动同步）

验收：导入不合格行可定位；普通用户不能修改采购字段或恢复、审批使用状态；待批申请及已用完标记在增量更新后仍保留。

## Phase 3：分析工具

- Sanger 单序列分析 API 与 R 适配层
- Nanopore 解析与编辑效率结果
- 文件重命名预览与 ZIP 导出
- CSV/XLSX 结果下载

验收：使用固定脱敏 fixtures 得到稳定结果；分析结果可下载；不产生长期归档。

## Phase 4：联调与交付

- 权限、上传安全、并发和清理策略测试
- windows-wg 启动/停止/备份恢复文档
- 生产环境变量清单、管理员操作手册
- 发布第一个可用版本（V1）

## 主要风险

- EditR 算法与新 API 的输入输出不一致：先建立 fixtures 和黄金结果。
- windows-wg 为老版本 Windows（LTSC 2019）且仅 8 GB 内存、与打印服务共用：安装前核对 Node.js/PostgreSQL/R 版本兼容性，所有路径通过环境变量配置，Nanopore 限制任务大小与并发。
- 大型 Nanopore 文件占用空间：限制单任务大小、并发数和 TTL。
- 原始表格列名漂移：导入器采用列别名映射并提供预览确认。
