# 物料采购记录、已用完审批与增量更新

## 当前范围与部署状态

完整录入 OA 导出的 21 个业务字段和所有部门采购记录，页面继续显示现有 10 列。展示范围为用户选定的两个部门，具体值仅存于忽略的本地环境配置和服务器受限配置，不写入源码、测试或文档。

2026-10-15 用户确认提交、推送和部署后，已在 windows-wg 部署网页、迁移数据库并启用每周 OA 增量同步。升级前已备份数据库、应用包和配置，原有记录身份保留。部署证据和回滚路径见 `../progress/2026-10-15-materials-oa-deploy.md`。

## 采购记录身份

一行代表一条采购记录，不按名称或单独物料编码去重。历史代码未记载单独物料编码去重的业务依据，该逻辑已移除。

增量更新按「采购单编码＋物料编码」匹配，保留原数据库行 ID。同名不同编号、同编号不同采购单均分别保存。缺少组合键、同一文件内组合重复或出现无法解析的记录时，整次提交失败，不任意选第一条。

名称、部门、请购人和收货状态不参与记录身份。若 OA 修改采购单编码或物料编码，则视作新记录，旧记录保留；需要跨编号追踪时，应先有可靠的 OA 记录 ID 或确认额外业务规则。

## 展示部门

网页服务读取 `MATERIAL_DISPLAY_DEPARTMENTS_JSON`，例如 `MATERIAL_DISPLAY_DEPARTMENTS_JSON='["示例部门甲","示例部门乙"]'`。本机放在 `apps/web/.env.local`，服务器放在既有 `lab.env`。本机 dotenv 可使用外层单引号；服务器由 PowerShell 5.1 读取，须使用无外层引号的原始 JSON，中文采用 ASCII 的 `\uXXXX` 转义。真实值不进入安装包。

部门条件在查询时应用，确保列表、总数、分页和筛选候选一致；不是下载一页以后再在浏览器删行。导入程序不应用展示范围，所有部门均入库。未配置时展示空列表，配置格式错误时报错，不默认展示所有部门。单条状态操作和后台审批也限制在同一展示范围内。

## 已用完申请与审批

本地标记独立于 OA 的「状态」和「收货状态」，关联单次采购记录，全员共享。

| 操作 | 普通成员 | 管理员 |
|---|---|---|
| 申请已用完 | 点击后必须二次确认，提交待审批申请 | 可直接标记为已用完 |
| 批准、驳回申请 | 无权限 | 后台可批量处理，单次最多 500 条 |
| 恢复已用完记录 | 无权限 | 可以恢复显示 |
| 查看、复制已用完记录 | 可以 | 可以 |

申请批准前仍在默认列表显示，并注明待批准；不因一个未审批的点击而立即隐藏。重复申请保留首次申请人与时间。批准后默认隐藏，勾选「仅显示已用完物料」后可查询。管理员恢复时清除当前标记和申请信息；操作历史保留在审计日志中。

申请、标记和恢复按钮及待批准提示放在物料编码下方，使用较小的次要文字，不新增主展示列。需要再次采购时，直接选中页面上的物料信息复制，不提供额外复制按钮或面板。

管理员后台入口 `/admin/materials`，可从物料页或导航进入，支持本页全选、批量批准和驳回。列表不暴露给普通成员。

## 增量同步

- 新记录插入，默认未用完且没有申请。
- 旧记录只更新 OA 业务字段，保留原 ID、本地已用完标记、申请人、批准操作人和时间。
- 不变的记录不重复写入；源文件暂时缺失的旧记录继续保留，不删除。
- 手动导入和定时任务共用 `importMaterialRows`，均在事务中写入；失败回滚，不再整表删除。
- `009_material_usage.sql` 新增本地状态字段和采购组合唯一约束，不清洗或删除历史记录。既有组合重复会导致迁移失败并回滚，须先人工核对。
- 迁移增加 `is_used_up`、`used_up_at/by`、`used_up_requested_at/by`、`updated_at`；申请批准时保留原申请信息，恢复或驳回时清除当前申请。审计日志记录操作人和记录 ID，不写业务明细。

## 每周任务

每周六服务器时间 03:00 重新登录 OA 并通过网页导出。导出配置设置 `OA_LAB_ENV_FILE` 后，下载核验成功即调用独立增量入口，读取本机既有 `lab.env` 的数据库配置；不新增工作台登录账号、网络接口或 API token。留空则只导出。

网页与迁移已部署，同步已启用。任务使用现有管理员账号的 S4U 无密码登录，无需保持交互登录；OA 会话仍每次新建。失败不自动重试，原下载文件保留。运行日志只包含阶段、固定错误码、通用文件名和新增/更新/未变化计数，不写凭证或采购明细。

## 回滚边界

生产已迁移并完成首次增量入库，回滚会影响后续数据，执行前须明确确认恢复时点。不能直接回退到旧的整表替换导入程序，否则旧逻辑可能删除新保存的标记；应先停用同步并按备份或经过确认的兼容方案回滚。
