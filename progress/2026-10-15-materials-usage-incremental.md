# 部门物料已用完审批与增量更新（仅本地）

## What was done

- 根据用户回复继续本地实现和隔离测试；两个指定展示部门仅保存到忽略的 `apps/web/.env.local`，源码和文档仅使用虚构部门示例。未部署或迁移服务器。
- 后端保留所有部门的 21 个采购字段，页面维持 10 个主展示列。列表、分页、总数、筛选候选和状态操作使用一致的展示部门范围；默认隐藏已用完记录，支持仅显示已用完。
- 新增迁移 `009_material_usage.sql`：采购单编码＋物料编码唯一组合、本地已用完及申请字段、操作人/时间与更新时间。不合并或删除旧记录，组合冲突会使迁移失败并回滚。
- 普通成员点击后需二次确认，提交待批准申请；批准前记录仍显示。管理员可直接标记、恢复，并在 `/admin/materials` 后台本页全选、批量批准或驳回。服务端校验权限，普通成员不能恢复或审批。
- 按采购记录增量写入，保留旧行 ID、本地申请及标记；新采购默认未用完，不变记录不写入，源文件缺失的旧记录保留。缺少采购组合键、文件内组合重复或解析不完整时整次拒绝。
- 手动导入和 OA 任务共用写入逻辑。OA 下载完成后按 `OA_LAB_ENV_FILE` 配置调用独立编译入口，读取本机既有数据库配置；不新增工作台账号、网络 API 或 token。每周六 03:00 的任务代码保持准备状态，未注册或启用。
- 新增采购信息复制操作，内网 HTTP 剪贴板不可用时显示选中文本框；不自动提交 OA 采购单。更新相关数据模型、接口、架构、部署、需求与回滚文档。
- 开发依赖新增固定版本 PGlite（内存 PostgreSQL 测试）和 esbuild（独立入库入口打包）。审计客户端类型缩小为仅 query，支持同一写入函数用于网页事务和本机客户端，其他审计行为保持不变。
